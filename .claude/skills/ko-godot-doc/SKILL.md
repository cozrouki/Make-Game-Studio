# /ko-godot-doc — Godot 게임 코드 문서화

> 출처: Godot 기여 문서(godotengine/godot-contributing-docs, CC BY 3.0)의 "Contribute documentation" 원칙과
> "Writing guidelines" 를 게임 코드에 맞게 옮기고 고쳐 썼다. 문서 주석 문법은 Godot 4.7 공식 문서
> "GDScript documentation comments" 를 따른다 (2026-11-04 확인) — `.claude/docs/ATTRIBUTION.md`.

GDScript 의 `##` 문서 주석은 에디터 도움말(F1)에 클래스 페이지로 뜨고, `@export` 변수 설명은 인스펙터 툴팁이 된다. 이 스킬은 그 설명을 **쓰는 법**과 **빠진 곳 찾기**를 맡는다.

## 0. 엔진 확인 — 먼저

`project.yaml` 의 `engine.name`(없으면 표지 파일 `project.godot`)이 Godot 이 아니면 아무것도 하지 않고 **"엔진이 Godot 이 아니라 하지 않음 — <엔진>"** 이라고 보고한다. 엔진 판정 순서는 `.claude/docs/engine-layers.md`.

범위 인수가 없으면 `project.yaml` 의 코드 루트(Godot 기본 `src/`)를 쓴다. `addons/` · `.godot/` 는 서드파티 · 생성물이라 뺀다.

## 1. audit — 빠진 곳 찾기

```bash
python .agent/tools/godot/godot_doc_audit.py <경로>          # 사람이 읽는 목록
python .agent/tools/godot/godot_doc_audit.py --json <경로>   # 집계용
```

| 규칙 | 무엇 | 등급 |
|---|---|---|
| GD001 | 공개 멤버(signal · const · enum · `@export` var · 공개 var · 공개 func · 내부 class)에 `##` 없음 | 누락 |
| GD002 | `class_name` 스크립트에 스크립트 설명(맨 위 `##` 블록) 없음 | 누락 |
| GD003 | `@tutorial  :` 처럼 태그 이름과 콜론 사이 공백 — 태그가 **조용히 무시된다** | 누락 |
| GD004 | 한 멤버에 `@deprecated` 와 `@experimental` 을 함께 씀 | 누락 |
| GD005 | `[codeblock]` 안의 탭 — 파서가 지운다 | 누락 |
| GD006 | 금지어(단순히 · 그냥 · 쉽게 · simple · just …) | 볼 것 |
| GD007 | 설명이 멤버 이름만 되풀이 (`## Sets the speed.` — `set_speed`) | 볼 것 |

`_` 로 시작하는 멤버(비공개 · `_ready` 같은 엔진 콜백)와 `@onready` 노드 참조는 GD001 에서 뺀다. 오탐은 그 줄이나 윗줄에 `# godot-doc: ignore GD001` 과 이유를 적는다.

**판정**: 누락 0 → **PASS** · 누락 있음 → **CONCERNS** · 검사한 `.gd` 가 0개 → **NOT ASSESSED** (이유를 함께 적는다). "볼 것" 은 판정을 바꾸지 않는다. 종료 코드는 판정과 무관하게 0 이다 — 문서 누락은 커밋을 막을 일이 아니다.

**C# 은 검사하지 않는다.** 결과의 "C# 파일 N개 검사 안 함" 줄을 보고서에 그대로 옮긴다. C# 프로젝트에서 NOT ASSESSED 가 나오면 "문서가 다 있다" 가 아니라 "보지 못했다" 이다.

## 2. write — 설명 쓰기

파일 하나(또는 audit 결과의 누락 목록)를 받아 설명을 채운다. 설명은 주석만 바꾸지만 게임 코드 파일을 고치는 일이다 — **쓰기 전에** 파일별로 넣을 설명(멤버 · 문구)과 "모르는 것" 목록을 먼저 보여 주고, "May I write these doc comments to `<파일>`?" 로 승인을 받은 뒤에만 Edit 한다. 코드(주석이 아닌 줄)는 바꾸지 않는다.

### 2-1. 쓰기 전에 — 아는 것만 쓴다

- 멤버마다 **코드를 읽고** 쓴다. 호출하는 곳 · 테스트 · 연결된 시그널 · 관련 GDD(`design/`)까지 본다. 이름만 보고 짐작한 설명은 쓰지 않는다.
- **모르면 비워 둔다.** 동작을 확신할 수 없는 멤버는 설명을 쓰지 않고 보고서의 **"모르는 것"** 목록에 이유와 함께 남긴다 (예: "`apply_knockback` — 넉백 방향 부호가 호출하는 곳마다 다름, 의도 확인 필요"). 그럴듯한 추측은 틀린 문서보다 나쁘다 — 다음 사람이 그것을 믿는다.
- **무성의한 설명 금지.** `## 속도.` (`speed`) · `## Sets the speed.` (`set_speed`) 처럼 이름을 되풀이하는 설명은 정보가 0 이다. 단위 · 범위 · 결과 · 조건 · 반환값을 쓴다.

### 2-2. 어디에, 어떤 문법으로

- 설명은 멤버 **바로 윗줄**에 `##` 로 쓴다. 빈 줄이 끼면 연결이 끊긴다. 여러 줄이면 줄마다 `##` 로 시작한다. 짧으면 같은 줄 뒤에 써도 된다 (`signal died ## 체력이 0 이 될 때.` — enum 값도 된다).
- 스크립트 설명은 맨 위(`extends` · `class_name` 아래)에 둔다. 첫 줄이 **짧은 설명**(태그 없음), 빈 `##` 한 줄 뒤가 **자세한 설명**, 태그는 맨 끝.
- 여러 줄 설명은 앞뒤 공백을 지우고 **공백 하나로 이어 붙여진다.** 진짜 줄바꿈은 `[br]`.
- 태그 — 스크립트: `@tutorial: <url>` · `@tutorial(<제목>): <url>` · `@deprecated[: <이유>]` · `@experimental[: <이유>]`. 멤버: `@deprecated` · `@experimental`. 태그는 줄 맨 앞에 쓰고, **이름과 콜론 사이에 공백을 넣지 않는다**(넣으면 무시된다). 둘을 함께 쓰지 않는다.
- 참조는 BBCode 로 — `[ClassName]` · `[member 이름]` · `[method 이름]` · `[signal 이름]` · `[constant 이름]` · `[enum 이름]` · `[param 이름]`(매개변수, 코드 모양). 다른 클래스는 `[method Class.name]`. 글자 모양: `[b]` · `[i]` · `[code]` · `[kbd]` · `[url=...]`, 문자 `[` `]` 는 `[lb]` `[rb]`.
- 코드 예는 `[codeblock]` … `[/codeblock]`. 들여쓰기는 **공백 4칸**(탭은 지워진다). `lang=text` 는 강조 없음, `lang=csharp` 는 .NET 판에서만 강조.

### 2-3. 어떻게 쓰나 — Godot 문서 작성 지침을 한국어 게임 코드에

| 원칙 | 하지 말 것 | 할 것 |
|---|---|---|
| 주어를 멤버로, 능동태 | `이 메서드는 일부 적에서만 구현된다.` | `일부 적만 이 메서드를 구현한다.` |
| 정확한 동사 — "설정한다" 만으로 끝내지 않는다 | `## 속도를 [param v] 로 설정한다.` | `## 수평 이동 속도를 [param v] 픽셀/초로 바꾼다. 점프 중에는 다음 착지 때 적용된다.` |
| 금지어 — 정보 없이 길이만 는다 | 단순히 · 그냥 · 쉽게 · 기본적으로 · 당연히 · 실제로 | 지운다. 대신 무엇을 하는지 쓴다 |
| 짧은 설명은 역할 개요 (200자 이내) | `## 적.` | `## 플레이어를 쫓다가 사거리에 들면 근접 공격하는 지상 적. 체력 · 속도는 [EnemyStats] 자원에서 읽는다.` |
| 반환값은 끝에 "…를 반환한다" | `## 반환된 값은 남은 체력이다.` | `## 피해를 적용한다. 남은 체력을 반환한다.` (`get_` · `set_` 은 생략 가능) |
| bool 은 "true 면" | `## 무적 여부를 제어한다.` | `## [code]true[/code] 면 피해를 받지 않는다.` |
| 값 · 매개변수는 코드 모양 | `## amount 만큼 회복` | `## [param amount] 만큼 회복한다.` |
| 명시적 참조 — "전자 · 후자" 금지 | `## 후자가 우선한다.` | `## [member shield] 가 [member hp] 보다 먼저 깎인다.` |
| 실제 예 — foo · my_var 금지 | `var my_var = 10` | `var jump_velocity := -400.0` |

- 언어는 팀 문서 언어를 따른다 (이 템플릿 기본은 한국어 — `.claude/rules/doc-writing.md`). 한 프로젝트 안에서 섞지 않는다.
- **타입 표기는 프로젝트 규칙이 이긴다.** Godot 엔진 문서의 코드 예는 일부러 동적 타입으로 쓰지만, 이 템플릿의 게임 코드는 정적 타입이다 (`.claude/rules/gameplay-code.md` Godot 절). `[codeblock]` 예도 정적 타입으로 쓴다.
- 구현하는 설계 문서가 있으면 스크립트 설명에 경로를 적는다 (`gameplay-code.md` — "코드 주석에 어떤 design doc 을 구현하는지"). `@tutorial` 은 URL 용이라 저장소 안 경로에는 쓰지 않는다.

### 2-4. C#

Godot C# 스크립트에는 C# 표준 XML 문서 주석(`///` + `<summary>`)을 쓴다 — IDE 툴팁과 생성 문서에 쓰인다. **Godot 에디터 도움말에 C# 문서 주석이 뜨는지는 이 저장소의 엔진 레퍼런스로 확인하지 못했다 (NOT SOURCEABLE).** 뜬다고 약속하지 않는다. 2-1 · 2-3 의 원칙(아는 것만 · 이름 되풀이 금지 · 금지어)은 그대로 적용된다.

### 2-5. 고친 뒤

같은 범위로 audit 를 다시 돌려 판정을 확인한다. 그다음 문서가 실제로 만들어지는지 본다 — 둘 중 하나:

- 에디터에서 F1(도움말 검색)으로 클래스 페이지를 연다.
- 에디터 창 없이: `godot --headless --path . --gdscript-docs <src 경로>` 는 GDScript 파일의 문서 주석으로 API 레퍼런스를 만든다 (Godot 4.7 명령줄 문서, 2026-11-04 확인). 결과는 임시 폴더로 받는다 — 저장소에 쓰지 않는다.

둘 다 못 했으면 보고서에 "에디터 도움말 미확인" 이라고 적는다.

## 3. 보고서

```
## Godot 문서화 — <범위>
판정: PASS | CONCERNS | NOT ASSESSED (<이유>)
- .gd <N>개 · 선언 <N>개 · 누락 GD001 <n> · GD002 <n> … · 볼 것 GD006 <n> · GD007 <n>
- C# 파일 <N>개 검사 안 함
- 이번에 쓴 설명: <파일:멤버 목록>
- 모르는 것 (설명을 쓰지 않음): <멤버 — 이유>
- 에디터 도움말: 확인함 | 미확인
```

"모르는 것" 이 있으면 판정과 별개로 맨 위에 적는다 — 그 멤버는 코드 주인이 답해야 한다.

## 4. 다음 단계

- **CONCERNS** → `/ko-godot-doc write <파일>` 로 누락을 채우고 audit 를 다시 돌린다.
- **"모르는 것" 이 있음** → 코드 주인에게 묻는다. 동작이 의도와 다르면 문서가 아니라 버그다 — `/ko-diagnose`.
- **설명을 쓰다 설계와 코드가 어긋난 곳을 찾음** → `/ko-code-review` 로 넘긴다 (문서로 어긋남을 덮지 않는다).
- **PASS** → 변경을 커밋한다 (스튜디오 모드면 dev 영역).
