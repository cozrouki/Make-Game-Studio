# /ko-narrative-lint — 내러티브 일관성 검사

`/team-narrative` · `writer` 에이전트는 이야기와 대사를 **쓴다**. 이 스킬은 써 둔 대사를 **기계로 훑어** 캐릭터 목소리와 세계 설정에서 벗어난 줄을 후보로 뽑는다. 판정은 사람이 한다 — 도구는 의심만 낸다.

> 방법 참고: 이민수, 『게임 기획 실무에서 바로 쓰는 AI·클로드 코드 활용법』 5부(내러티브 — 문서 층 · 정합성 검증 · 대사 톤 일관성). 원문은 옮기지 않고 이 템플릿 구조로 다시 썼다. 원문: `/ext gdpractice 5부` (선택 설치 · 비상업 라이선스).

도구: `python .agent/tools/design/narrative_lint.py` (표준 라이브러리만). 기본 경로: `design/narrative/voices/` · `design/narrative/dialogue/` · `design/narrative/rulebook.json`.

## 언제

- 대사 초안이 나온 뒤, **녹음 · 현지화 · 빌드 반영 전**. 텍스트 단계에서 고치는 게 가장 싸다 — 녹음 뒤에 찾으면 재녹음이다.
- AI 가 대사를 대량으로 만들었을 때 (`/ko-content-pattern tiers` 에서 대사가 `rulebook+ai` · `ai-first` 인 경우).
- 도입 순서: 보이스 프로필 → 캐릭터 금기 어휘 → 시간선 → 세계 금기어 · 세력. 한 번에 다 만들지 않는다.

## setup <캐릭터 ...> — 프로필 · 룰북 만들기

1. 이미 쓴 대사가 있으면 먼저 `stats` 로 캐릭터별 대사 수 · 평균 길이 · 말 높이 분포를 본다. 프로필 값은 이 실측에서 시작한다 (지어내지 않는다).
2. 캐릭터마다 `design/narrative/voices/<캐릭터>.md`:
   ```markdown
   ---
   id: VOICE-mira
   title: 미라 보이스
   type: voice
   character: 미라
   abstraction: L2
   status: draft
   owner: 기획
   updated: 2026-10-30
   speech_level: 해요체          # 해요체 · 하십시오체 · 해체(반말) · 혼합
   sentence_max: 40              # 한 대사 최대 글자 수
   forbidden: [젠장]             # 이 캐릭터가 쓰지 않는 말
   forbidden_ok_when: [회상]     # 대사 줄에 이 태그가 있으면 금기 검사 생략
   ---
   어휘 영역 · 감정을 드러내는 방식 · 예시 대사 3~5줄 · 금기의 예외가 되는 상황
   ```
   본문(사람이 읽는 설명)이 프런트매터(기계가 읽는 값)보다 중요하다 — writer 에이전트가 대사를 쓸 때 이 본문을 읽는다.
3. 룰북 `design/narrative/rulebook.json` — 세계 금기어(`world_forbidden` — 오탐 낱말은 `except`), 시간선(`timeline` — id · order · 사건), 시점 제약(`facts` — 어느 시간선 뒤에만 나올 수 있는 말), 세력 적대 관계(`factions`). 형식은 `narrative_lint.py` docstring.
4. 프로필 · 룰북은 `/ko-design-graph` 의 문서이기도 하다 (`type: voice` · `lore`) — `lore` 문서에서 `derives_from` 으로 필러(L0)를 가리킨다.

## check [대사 경로 ...]

대사 형식: `캐릭터: 대사` · `캐릭터 [태그]: 대사`, 장면 머리줄 `## 장면 S03 @ T12` (`@` 뒤 = 시간선 id).

```
python .agent/tools/design/narrative_lint.py check [--dialogue <파일·폴더>] [--json]
```

| 규칙 | 의심 | 사람이 고를 것 |
|---|---|---|
| NL001 | 캐릭터 금기 어휘 (예외 태그면 info) | 위반 · 의도(감정 폭발 등 — 태그를 단다) · 과민(금기 목록 수정) |
| NL002 | 문장 길이 초과 | 위반 · 의도 · 과민(sentence_max 조정) |
| NL003 | 말 높이 불일치 (판정 가능 문장 중 비율) | 위반 · 의도(관계 변화 — 장면 메모) · 과민 |
| NL004 | 세계 금기어 | 위반 · 과민(`except` 추가) |
| NL005 | 시간선보다 앞선 장면에 나온 말 | 위반 · 장면 순서 오류 |
| NL006 | 프로필 없는 캐릭터 | 프로필 만들기 · 단역이면 그대로 |
| NL007 | 한쪽만 적대인 세력 관계 | 룰북 수정 |

보고 순서:
1. **판정**: 입력 형식 오류(종료 코드 1)면 NOT ASSESSED 와 오류 줄. 그 밖에는 후보 수를 규칙별로. **"검사 안 함"** 줄(룰북 없음 · 프로필 없는 캐릭터 · 시간선 없는 장면 · '혼합' 프로필)은 반드시 같이 보여 준다 — 검사 안 한 캐릭터가 깨끗한 것처럼 읽히지 않게.
2. 후보를 캐릭터별로 묶어 원문 줄 번호와 함께 보여 주고, 사용자가 줄마다 **위반 / 의도 / 과민** 을 고르게 한다 (많으면 규칙별로 한 번에).
3. 위반 → 대사 수정안 제시(승인 후 반영). 의도 → 대사 줄에 태그를 달거나 장면 메모. 과민 → 프로필 · 룰북 수정안.
4. 과민 판정이 반복되는 규칙은 프로필이 너무 빡빡하다는 뜻이다 — 값을 실측(`stats`)으로 다시 잡자고 제안한다. AI 가 만든 대사의 폐기 비율도 함께 보고하면 생성 강도를 정할 근거가 된다.

## 한계 (보고에 밝힌다)

- 말 높이는 형태소 분석 없이 **끝 글자**로 판정한다 — 명사로 끝나는 문장("바다", "어머니")을 반말로 오판할 수 있고, 해라체와 반말을 구분하지 않는다. 그래서 의심 후보다.
- 금기어 · 시간선은 **부분 문자열** 일치 — 활용형 · 띄어쓰기 변형은 놓치고, 다른 낱말 속 일치는 `except` 로만 피한다.
- "시간: 새벽" 같은 지문 줄이 대사로 읽힐 수 있다 (NL006 info 로 드러난다).
