# /ko-diagnose — 버그 진단 루프

어려운 버그를 위한 절차다. 단계를 건너뛰려면 이유를 명시한다.

> 출처: mattpocock/skills `diagnosing-bugs` (MIT) 를 Unity 용으로 옮기고 조정했다 — `.claude/docs/ATTRIBUTION.md`.

시작 전에 해당 게임의 `doc/{GameName}/architecture.md`(있으면)와 손대는 영역의 ADR 을 읽어 모듈 구조를 잡는다. 증상 · 로그 · 캡처를 보여 줄 때는 비밀 값(토큰 · 키 · 계정)을 `<REDACTED>` 로 가린다.

## 1단계: 재현 루프 만들기

**이 단계가 이 스킬의 전부다.** 이 버그에서 **red** 가 되는 **tight** 한 통과/실패 신호가 있으면 원인은 반드시 찾는다. 없으면 코드를 아무리 읽어도 소용없다. 여기에 시간을 가장 많이 쓴다.

### 루프를 만드는 방법 (대략 이 순서)

1. **실패하는 EditMode 테스트** — 로직이 MonoBehaviour 밖으로 분리되어 있으면 가장 빠르다. `mcp__UnityMCP__run_tests` (mode EditMode, 테스트 이름 필터) 또는 배치 모드 `Unity -batchmode -projectPath . -runTests -testPlatform EditMode -testFilter <이름> -testResults <경로>`
2. **실패하는 PlayMode 테스트** — 프레임 · 물리 · 코루틴 · 씬 로딩이 얽힌 버그. 최소 씬이나 코드로 구성한 GameObject 로 재현한다
3. **에디터 스크립트 / 메뉴 아이템 하네스** — `Scripts/Editor/` 에 임시 `[MenuItem]` 을 만들어 한 번 호출로 버그 경로를 태우고, 결과를 `Debug.Log` 로 남겨 `read_console` 로 읽는다
4. **기록 재생** — 입력 · 이벤트 · 저장 데이터를 파일로 떠서 해당 코드 경로에 그대로 다시 흘린다
5. **무작위 · 반복 루프** — "가끔 틀린다" 면 시드 고정 무작위 입력을 1000번 돌려 실패 모드를 찾는다
6. **이분 탐색 하네스** — 두 커밋 사이에 생긴 버그면 "그 상태로 테스트 실행 → 판정" 을 자동화해 `git bisect run` 으로 돌린다
7. **차이 비교 루프** — 같은 입력을 이전 버전 · 새 버전(또는 두 설정)으로 돌려 출력을 비교한다
8. **사람 개입 루프 (마지막 수단)** — 사람이 Play 모드에서 직접 조작해야만 한다면, 조작 절차 · 기대 결과 · 확인할 로그를 번호로 적어 사용자에게 주고 결과(콘솔 로그 · 스크린샷)를 받아 판정한다. 그래도 절차는 매번 같게 유지한다

### 루프 조이기

루프 하나가 생기면 더 **tight** 하게 만든다.

- 더 빠르게: 불필요한 씬 · 에셋 로딩 제거, 테스트 범위 좁히기, 도메인 리로드 없는 EditMode 로 내리기
- 더 날카롭게: "예외 없음" 이 아니라 사용자가 말한 **바로 그 증상**을 단언한다
- 더 결정적으로: `Random.InitState` 시드 고정, 시간 · deltaTime 주입, 물리 스텝 고정, 외부 입력 차단

30초짜리 불안정한 루프는 없는 것과 거의 같다. 2초짜리 결정적 루프가 목표다.

### 비결정적 버그

목표는 깔끔한 재현이 아니라 **재현율 높이기**다. 트리거를 100번 반복, 타이밍 창 좁히기, 프레임 지연 · `Time.timeScale` 조작, 스트레스 추가. 재현율 50% 는 디버깅할 수 있고 1% 는 못 한다.

### 루프를 도저히 못 만들 때

멈추고 그렇다고 말한다. 시도한 것을 나열하고 사용자에게 (a) 재현되는 환경 · 기기 접근, (b) 가린 로그 · Player.log · 프로파일러 캡처 · 타임스탬프 있는 녹화, (c) 임시 계측 코드를 빌드에 넣어도 되는지를 요청한다. 루프 없이 가설로 넘어가지 않는다.

### 완료 조건: red 가 되는 tight 한 루프

**명령 하나**(테스트 이름 · 메뉴 경로 · 스크립트)를 댈 수 있고, **이미 한 번 이상 실행해서** 호출과 출력을 보여 줬으며, 아래를 모두 만족하면 끝난다.

- [ ] **red 가능**: 실제 버그 코드 경로를 지나고 사용자의 증상을 단언한다. 고치면 green 이 된다
- [ ] **결정적**: 매번 같은 판정 (비결정 버그는 고정된 높은 재현율)
- [ ] **빠름**: 분 단위가 아니라 초 단위
- [ ] **에이전트 실행 가능**: 사람 없이 돌린다 (사람 개입은 8번 방식으로만)

이 명령이 생기기 전에 코드를 읽으며 원인 이론을 세우고 있다면 **멈춘다.** 곧장 가설로 뛰어드는 것이 이 스킬이 막으려는 실패다.

## 2단계: 재현 + 최소화

루프를 돌려 red 를 확인한다.

- [ ] 사용자가 말한 실패와 **같은** 실패다 (근처의 다른 실패가 아니다 — 다른 버그를 고치면 헛수고다)
- [ ] 여러 번 돌려도 재현된다 (비결정 버그는 디버깅 가능한 재현율)
- [ ] 정확한 증상(오류 메시지 · 틀린 값 · 프레임 시간)을 기록해 뒀다

그다음 **최소화**한다. 입력 · 호출자 · 설정 · 데이터 · 씬 오브젝트 · 단계를 **하나씩** 빼면서 매번 루프를 다시 돌리고, 실패에 꼭 필요한 것만 남긴다. 남은 요소 중 무엇을 빼도 green 이 되면 끝이다. 최소 재현은 3단계의 가설 범위를 줄이고 5단계의 회귀 테스트가 된다.

## 3단계: 가설

하나를 시험하기 전에 **3~5개 가설을 순위대로** 세운다. 가설 하나만 세우면 처음 떠오른 그럴듯한 생각에 고정된다.

각 가설은 **반증 가능**해야 한다.

> 형식: "<X> 가 원인이면 <Y 를 바꾸면> 버그가 사라지고 / <Z 를 바꾸면> 더 심해진다."

예측을 말할 수 없으면 느낌일 뿐이다 — 버리거나 다듬는다.

**순위 목록을 시험 전에 사용자에게 보여 준다.** 사용자는 "3번은 어제 바꿨다" 같은 지식으로 순위를 바로 바꾸거나 이미 배제한 가설을 알려 준다. 답을 기다리며 멈추지는 않는다 — 응답이 없으면 내 순위대로 진행한다.

## 4단계: 계측

각 탐침은 3단계의 예측 하나에 대응한다. **한 번에 변수 하나만** 바꾼다.

1. **디버거 · 인스펙터 확인** — 가능하면 중단점 하나가 로그 열 줄보다 낫다
2. **가설을 가르는 경계에 표적 로그**
3. "전부 로그 찍고 grep" 은 하지 않는다

**디버그 로그에는 고유 접두사를 단다** (예: `Debug.Log("[DEBUG-a4f2] ...")`). 정리할 때 grep 한 번이면 된다.

**성능 회귀 분기**: 로그는 대개 쓸모없다. 기준선부터 측정한다 — `mcp__UnityMCP__manage_profiler` 캡처, `Stopwatch` 타이밍 하네스, Profiler 마커. 그다음 이분 탐색한다. 측정이 먼저, 수정은 나중이다. 해결 패턴은 `/ko-perf-profile` 과 `.agent/skills/06-performance/` 를 참고한다.

## 5단계: 수정 + 회귀 테스트

회귀 테스트는 **수정 전에** 쓴다. 단, **올바른 접점(seam)** 이 있을 때만이다.

올바른 접점이란 호출 지점에서 실제로 일어나는 버그 패턴을 그대로 태우는 경계다. 접점이 너무 얕으면(여러 호출자가 얽혀야 나는 버그를 단일 호출 테스트로, MonoBehaviour 생명주기가 필요한 버그를 순수 EditMode 로) 그 테스트는 거짓 안심만 준다.

**올바른 접점이 없다면 그것 자체가 발견이다.** 기록한다 — 구조가 버그를 테스트로 고정하지 못하게 막고 있다는 뜻이다 (로직이 MonoBehaviour 에 묶임, static 싱글톤, 시간 · 랜덤 직접 호출 등). `/ko-code-review` 나 기술 부채(`/tech-debt`)로 넘긴다.

올바른 접점이 있으면:

1. 최소 재현을 그 접점의 실패하는 테스트로 만든다
2. 실패하는 것을 본다. 코드 · 픽스처를 일부러 바꿔 red 를 만들었다면 `git diff` 로 그 변경이 실제로 들어갔는지 확인하고 나서 믿는다
3. 수정한다
4. 통과하는 것을 본다
5. 원래(최소화 전) 시나리오로 1단계 루프를 다시 돌린다

## 6단계: 정리

끝났다고 말하기 전에 모두 확인한다.

- [ ] 원래 재현이 더는 재현되지 않는다 (1단계 루프 재실행)
- [ ] 회귀 테스트가 통과한다 (또는 접점이 없다는 사실을 기록했다)
- [ ] `[DEBUG-...]` 계측을 모두 지웠다 (접두사로 grep)
- [ ] 임시 하네스 · 메뉴 아이템 · 테스트 씬을 지웠거나 디버그용임이 분명한 위치로 옮겼다
- [ ] 맞았던 가설을 커밋 메시지(또는 `doc/work_log.md` 항목)에 적어 다음 사람이 배우게 한다
