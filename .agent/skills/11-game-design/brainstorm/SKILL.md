# Brainstorm — 게임 컨셉 아이디어 발굴

## 호출 시 동작

### 0. 준비

- 인수에서 장르/테마 힌트를 파싱한다 (없으면 개방형).
- `doc/{GameName}/architecture.md`, `doc/{GameName}/task.md` 가 있으면 읽어서 기존 컨텍스트를 파악한다.
- `production/session-state/active.md`의 STATUS 블록을 읽어 현재 작업 게임을 확인한다.

---

### Phase 1: Creative Discovery (창의적 탐색)

유저를 먼저 이해한다. 게임이 아닌 사람을 파악하는 것이 목적.

**감정적 앵커 질문** (AskUserQuestion 또는 대화로):
- 플레이하면서 진심으로 감동받거나 시간 가는 줄 몰랐던 게임 경험은?
- 게임에서 늘 원했지만 아직 찾지 못한 판타지나 권능감이 있다면?

**취향 프로파일**:
- 가장 많이 플레이한 게임 3개와 계속 돌아간 이유?
- 선호 장르와 기피 장르?
- 도전형 / 힐링형 / 서사형 / 표현형 중 어느 경험을 선호?

**실용적 제약** (샌드박스를 먼저 정의):
- 솔로 개발 vs 팀? 어떤 기술을 갖고 있는가?
- 타임라인: 몇 주 / 몇 달 / 몇 년?
- 플랫폼 제약? (PC 전용 / 모바일 / 콘솔)

위 답변을 **Creative Brief** — 감정 목표·취향·제약을 담은 3~5문장 요약 — 으로 종합하고 확인받는다.

---

### Phase 2: Concept Generation (컨셉 생성)

Creative Brief를 기반으로 **서로 다른 방향의 컨셉 3개**를 생성한다.

**기법 1 — Verb-First**: 핵심 플레이어 동사(건설·전투·탐색·생존·창조·발견)에서 출발
**기법 2 — Mashup**: 예상치 못한 두 요소 결합 ("로그라이크 + 목장 경영", "도시 건설 + 실시간 전투")
**기법 3 — Experience-First (MDA 역방향)**: 원하는 감정(Sensation / Fantasy / Narrative / Challenge / Discovery / Expression)에서 거꾸로 Mechanic을 도출

각 컨셉마다 제시:
- **작업 제목**
- **엘리베이터 피치** (10초 테스트 통과, 1~2문장)
- **핵심 동사** (가장 빈번한 플레이어 액션)
- **핵심 판타지** (감정적 약속)
- **유니크 훅** ("Like X, AND ALSO Y" 테스트 통과)
- **주요 MDA 미학** (어떤 감정이 지배하는가)
- **예상 범위** (소 / 중 / 대)
- **작동 이유** (1문장, 시장/타겟 적합성)
- **최대 리스크** (1문장, 가장 어려운 미답 질문)

AskUserQuestion으로 선택 또는 조합 요청. 압박하지 말 것.

---

### Phase 3: Core Loop Design (핵심 루프 설계)

선택된 컨셉의 핵심 루프를 구조화된 질문으로 빌드.

**30초 루프** (순간순간):
- 플레이어가 가장 자주 하는 물리적 행동은?
- 이 행동 자체가 내재적으로 재미있는가? (보상·진행·스토리 없이도?)

**5분 루프** (단기 목표):
- "한 판만 더" 심리가 발동되는 지점은?
- 이 레벨에서 플레이어가 내리는 선택은?

**세션 루프** (30~120분):
- 완전한 세션의 모습은? 자연스러운 종료 지점은?
- 게임 안 할 때도 생각나게 하는 "훅"은?

**진행 루프** (일/주):
- 플레이어는 어떻게 성장하는가? (능력 / 지식 / 선택지 / 스토리)
- 게임의 "끝"은 언제인가?

**SDT 동기 분석**:
- **자율성**: 의미 있는 선택이 충분히 있는가?
- **유능감**: 플레이어가 실력 향상을 느끼는가?
- **관계성**: 캐릭터·세계·다른 플레이어와의 연결감은?

---

### Phase 4: Pillars & Anti-Pillars (설계 기둥)

**기둥 3~5개**를 협업으로 정의:
- 이름 + 한 문장 정의
- 설계 테스트: "X와 Y 사이에서 고민할 때 이 기둥은 __을 선택하라고 한다"
- 기둥들이 서로 긴장 관계를 이루어야 효과적

**안티-기둥 3개 이상** (이 게임이 하지 않을 것):
- "우리는 [기능]을 하지 않는다. [기둥]을 훼손하기 때문이다"

---

### Phase 5: Player Type Validation (플레이어 타입 검증)

Bartle 분류와 Quantic Foundry 동기 모델로 타겟 검증:
- **1차 플레이어 타입**: 이 게임을 열정적으로 사랑할 사람은?
- **2차 어필**: 부수적으로 즐길 수 있는 타입은?
- **안 맞는 타입**: 이 게임을 싫어할 사람은?
- **시장 검증**: 유사한 타겟을 가진 성공 사례와 그 교훈은?

---

### Phase 6: Scope & Feasibility (범위 및 실현 가능성)

- **엔진 추천** (Unity / Godot / Unreal) + 이유 (컨셉 요구사항, 팀 기술, 플랫폼)
- **아트 파이프라인**: 아트 스타일과 노동 강도
- **콘텐츠 범위**: 레벨/구역 수, 아이템 수, 예상 플레이 시간
- **MVP 정의**: 핵심 루프가 재미있는지 검증할 최소 빌드
- **최대 리스크**: 기술·디자인·시장 리스크
- **범위 티어**: 풀 비전 vs 시간 부족 시 출시 가능한 것

---

### 출력 및 저장

협업을 통해 컨셉이 확정되면:

1. 유저에게 저장 경로 확인: `doc/{GameName}/game-concept.md`
2. "이 파일을 저장해도 될까요?" 확인 후 저장
3. `production/session-state/active.md` STATUS 블록 업데이트

**다음 단계 안내**:
- `/map-systems` — 컨셉을 개별 시스템으로 분해
- `/design-system {시스템명}` — 개별 시스템 GDD 작성
- `/design-review doc/{GameName}/game-concept.md` — 완성도 검토
